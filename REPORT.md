# Звіт до лабораторної роботи № 1

## 1. Тема, номер і варіант

**Предметна область:** Магазин техніки. **Номер варіанта:** 10. **Операційна система:** Windows 11 (розробка), Ubuntu/macOS/Windows (CI).

## 2. Мета роботи

Пройти повний шлях від створення репозиторію й налаштування інфраструктури до версії простої консольної програми, яку можна відтворено зібрати й запустити на Windows, macOS та Ubuntu.

## 3. Постановка задачі

Створити консольну програму для обробки товарів магазину техніки. Формат запису: `name:String; category:String; price:double; warrantyMonths:int; stock:int`. Програма обчислює 4 показники: кількість коректних записів, середня ціна, найдовша гарантія (міс), загальна кількість на складі (шт).

## 4. Структура програми

- `data/input.csv` — вхідні дані для тестування.
- `src/main/java/ua/lpnu/kzp/Main.java` — головний клас: читання, розбір і валідація полів, обчислення показників, формування звіту.
- `src/main/java/ua/lpnu/kzp/VersionInfo.java` — читає версію й номер збірки для `--version`.
- `src/test/java/ua/lpnu/kzp/MainTest.java` — модульні тести (JUnit 5).
- `out/report.txt` — згенерований файл зі звітом.

## 5. Інфраструктура

- **Maven:** управління залежностями та збіркою (`pom.xml`, `mvnw`).
- **Залежності:** JUnit 5 (`junit-jupiter`) для тестування.
- **Аналізатор:** SpotBugs прив'язаний до фази `verify`.
- **Пакування:** `maven-shade-plugin` створює виконуваний JAR.
- **CI/CD:** GitHub Actions (матриця ubuntu-latest, windows-latest, macos-latest), публікує JAR як артефакт.

## 6. Приклади роботи

Вхідні дані (фрагмент `data/input.csv`):

```
Lenovo IdeaPad 3;Ноутбук;21999.00;24;5
Asus Vivobook 15;Ноутбук;18999.50;12;0
Dell Inspiron 14;Ноутбук;24999.00;36;3
;Периферія;999.00;6;5
Razer DeathAdder;Периферія;-150.00;6;20
```

Файл звіту (`out/report.txt`, фрагмент базових показників):

```
Коректних записів: 7
Середня ціна: 13799.07 грн
Найдовша гарантія: 36 міс
Загальна кількість на складі: 38 шт
Помилок: 5
Рядок 8: порожнє обов'язкове текстове поле
Рядок 9: числові поля не можуть бути від'ємними
Рядок 10: числове поле має помилковий формат
Рядок 11: невідома категорія товару "Монітор"
Рядок 12: очікується 5 полів, отримано 4
```

## 7. Тестування

Локально виконано команди `mvnw test` та `mvnw verify`. Перевірено коректний рядок, порожній рядок, неправильну кількість полів, нечислове поле, від'ємне значення та файл без коректних записів. Збірка проходить перевірку CI у GitHub Actions на трьох ОС.

## 8. Документація

Клас `Main` (метод `main` і пакетний метод `buildReport`), `VersionInfo` та `MainTest` задокументовано через javadoc.

## 10. Відповіді на контрольні питання

1. **Яке призначення файла pom.xml?** Файл опису Maven-проєкту: координати артефакта, версія Java, кодування, залежності й плагіни збірки.
2. **Чим відрізняються фази test, verify і package у Maven?** `test` запускає модульні тести; `verify` додатково виконує статичний аналізатор; `package` формує виконуваний JAR. Кожна наступна фаза виконує всі попередні.
3. **Навіщо потрібен Maven Wrapper?** Дає змогу збирати проєкт без попередньо встановленого Maven і гарантує однакову версію інструменту на всіх машинах і в CI.
4. **Яку роль відіграє метод main?** Це точка входу Java-програми — саме з нього JVM починає виконання.
5. **Чим примітивний тип відрізняється від String?** Примітивний тип зберігає значення напряму й не має методів; `String` — посилальний тип з масивом символів і набором методів обробки тексту.
6. **Чому середнє потрібно обчислювати в double, навіть якщо сума й кількість мають тип int?** Ділення `int/int` відкидає дробову частину; явне приведення до `double` зберігає точність результату.
7. **Що станеться, якщо Integer.parseInt отримає рядок "abc"?** Буде викинуто `NumberFormatException`, бо рядок не можна інтерпретувати як ціле число.
8. **Чому не можна мовчки пропускати рядок із помилкою?** Це призведе до прихованої втрати даних; користувач має бачити номер рядка й причину, щоб відрізнити «порожній вхід» від «пошкоджених даних».
9. **Як String.split(";", -1) обробляє порожнє останнє поле?** Параметр `-1` зберігає порожні елементи в кінці масиву; без нього `split` відкидає їх.
10. **Чому для шляхів краще використовувати Path.of, а не "data\\input.csv"?** `Path.of` сам обирає правильний роздільник директорій для Windows, macOS та Ubuntu, забезпечуючи кросплатформність.
11. **Навіщо явно задавати StandardCharsets.UTF_8?** Щоб українські символи коректно читалися й записувалися незалежно від кодування операційної системи за замовчуванням.
12. **Чим %n відрізняється від \n у форматованому виводі?** `%n` підставляє символ переходу рядка, прийнятий для поточної ОС; `\n` — завжди лише Unix-варіант.
13. **Які дані потрібно перевірити у вашому варіанті?** Непорожні назву й категорію; скінченну невід'ємну ціну; невід'ємні гарантію й залишок; правильну кількість полів і коректний числовий формат.
14. **Які тести виявлять помилку в обчисленні середнього?** Тест із сумою, що не ділиться націло (перевірка дробової частини), і тест із порожнім набором коректних записів (ділення на нуль).
15. **Яке призначення статичного аналізатора?** Перевіряє байт-код без запуску програми, знаходячи потенційні дефекти й погані практики.
16. **Яку роль виконує GitHub Actions?** Автоматизує CI: збирає проєкт і запускає тести й аналізатор на кількох ОС під час кожного пушу чи pull request.
17. **Чим версія програми відрізняється від номера збірки CI і чому їх розділяє знак +, а не крапка?** Версія описує стан коду (SemVer, `<version>` у `pom.xml`), номер збірки — конкретний запуск CI (`build.number`). Знак `+` відокремлює метадані збірки, тому дві збірки з однаковою частиною до `+` залишаються тією самою версією.
18. **Що має містити GitHub Issue на дефект?** Короткий опис проблеми, кроки відтворення, очікуваний і фактичний результат.
19. **Що Ви повинні вказати у розділі звіту про академічну доброчесність?** Які інструменти ШІ використано, для яких завдань (ролі), та підтвердження особистої відповідальності за код.
20. **Яку роботу виконує агент DevOps, а яку — агент Валідатор?** DevOps налаштовує інфраструктуру (Maven, Wrapper, CI); Валідатор складає крайові випадки й перевіряє результати, оформлюючи дефекти як Issues.
21. **Який рядок вашої програми найскладніше пояснити і чому?** Блок `try { ... } catch (NumberFormatException exception) { errors.add(...); continue; }` усередині циклу `buildReport` — складно тому, що саме тут помилка одного рядка (зіпсоване число) не повинна зупиняти обробку решти файлу, а `continue` явно пропускає лише цей рядок, не перериваючи цикл.

## 11. Висновки

Створено першу версію консольного продукту для магазину техніки: програма читає записи, відкидає хибні дані з поясненням, обчислює чотири показники та формує звіт у консоль і файл. Налаштовано повну кросплатформну інфраструктуру (Maven, SpotBugs, JUnit 5, GitHub Actions), що відповідає вимогам Рівня 3. Цей код стане основою для лабораторної роботи № 2, де рядки й окремі змінні будуть замінені власним класом-сутністю.
